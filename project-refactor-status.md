### Found while testing Google auth live (both fixed, 2026-07-20)

Two separate real-world issues surfaced only once you actually clicked "Log in with Google" — neither was something static review could have caught:

1. **Clicking login showed a blank page, URL at `/auth/login?...`.** Streamlit only registers its `/auth/login`, `/auth/logout`, `/oauth2callback` routes once, at server process startup, gated on Authlib being importable (`streamlit/web/server/server.py`). Your `streamlit run` process had been started before `[auth]`/Authlib were fully in place, so it locked in a route table without auth support — Streamlit's own script auto-reload only re-runs `dashboard.py`, it never rebuilds the server's routes. Confirmed by curling `/auth/login` directly (with a manually-generated valid token) and seeing it fall through to the plain app shell instead of a redirect. **Fix: restart the Streamlit process** (not just rerun) — you did this.
2. **After restarting, login failed with `400: 'NoneType' object does not support item assignment`.** This is a genuine version-incompatibility bug, not a config mistake — traced it to `authlib.integrations.base_client.framework_integration.FrameworkIntegration.set_state_data`. Streamlit's Tornado integration always calls this with `session=None` (Tornado has no built-in session, so it relies entirely on its own cache). Authlib `1.7.2` (the version that happened to be installed — it was never actually pinned anywhere in this project) added an unconditional `session[key] = ...` write even in the cache-enabled branch, which crashes on `None`. Downloaded and diffed `set_state_data`/`get_state_data`/`clear_state_data` across Authlib 1.3.2 → 1.7.0 to confirm exactly where the regression landed: **introduced in 1.7.0**, absent in 1.6.5 and earlier. **Fix applied:** downgraded to `Authlib==1.6.5` in `py_envs` and added it to `py_envs/requirements.txt` (pinned, so a fresh `pip install -r requirements.txt` doesn't silently reintroduce 1.7.x). **You need to fully restart the Streamlit server once more** to pick up the downgraded library — a script rerun alone won't reload it.
